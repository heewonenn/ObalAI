# ObalAi

**Тамақ қалдықтарын азайтуға арналған ақылды платформа**

ObalAi дүкендерге, супермаркеттерге, кафелер мен мейрамханаларға жарамдылық мерзімі жақындаған өнімдер мен дайын тағамдарды жеңілдікпен ұсынуға көмектеседі. Сатып алушылар қолжетімді ұсыныстарды қарап, салыстырып, алдын ала брондап, жеткізуге немесе алып кетуге тапсырыс бере алады.

## Іске қосу (FastAPI + PostgreSQL + PySide6 + Веб-демо)

Жобаның негізгі бөлігі **Python** тілінде жазылған: **FastAPI + PostgreSQL + Alembic** (backend) және **PySide6** (desktop-қосымша). Сонымен қатар браузер арқылы жылдам көрсетуге арналған веб-демо (`/demo/`, Render) қолжетімді.

**[ObalAi жария веб-демосын ашу](https://obalai-demo.onrender.com/)**

### 1. Backend серверін іске қосу (PostgreSQL + FastAPI)

PostgreSQL жүйесінде `obalai` дерекқорын құрып, `backend/.env.example` үлгісін `backend/.env` файлына көшіріңіз. PostgreSQL құпиясөзін және JWT кілтін сол файлда баптаңыз. Содан кейін іске қосыңыз:

```powershell
cd backend
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app
```

Сервер `http://127.0.0.1:8000` мекенжайында іске қосылады ([веб-демо](http://127.0.0.1:8000/demo/), [Swagger UI](http://127.0.0.1:8000/docs), `/health`).

### 2. PySide6 desktop-қосымшасын іске қосу

Екінші терминалда desktop тәуелділіктерін орнатып, қосымшаны ашыңыз:

```powershell
python -m pip install -r desktop/requirements.txt
python desktop/run.py
```

Қашықтағы FastAPI серверіне (мысалы, Render) қосылу үшін `OBALAI_API_URL` орта айнымалысын орнатуға болады:

```powershell
$env:OBALAI_API_URL = "https://obalai-demo.onrender.com"
python desktop/run.py
```

### Render арқылы API жариялау

1. [Render Dashboard](https://dashboard.render.com/) ішінде **New → Blueprint** тармағын таңдаңыз.
2. `heewonenn/ObalAI` репозиторийін қосып, `main` тармағын және `render.yaml` файлын таңдаңыз.
3. Тізімдегі Python Web Service пен PostgreSQL ресурстарының **Free** тарифінде тұрғанын тексеріп, **Deploy Blueprint** түймесін басыңыз.

Blueprint PostgreSQL байланысын баптайды, JWT кілтін жасайды және серверді іске қоспас бұрын Alembic миграцияларын қолданады. [Render Free шектеулері](https://render.com/docs/free).

### API арқылы көрсету

[Swagger UI](http://127.0.0.1:8000/docs) арқылы:

1. `POST /api/auth/register` арқылы `seller` және `buyer` аккаунттарын бөлек email мекенжайымен тіркеңіз. `POST /api/auth/login` арқылы сатушы болып кіріп, `access_token` мәнін **Authorize** терезесіне енгізіңіз.
2. `POST /api/seller/store` арқылы `name`, `address` және `city` өрістерін беріп, дүкен ашыңыз. Әр сатушыға бір дүкен қарастырылған.
3. `POST /api/seller/batches` арқылы партия жариялаңыз. Мысалы, төмендегі JSON үлгісінде `expires_at` мәнін болашақ уақытқа қойыңыз. Уақыт белдеуін көрсетіңіз.

   ```json
   {
     "product": { "name": "Нан", "unit": "piece" },
     "quantity": "3",
     "regular_price": "1000.00",
     "discount_price": "700.00",
     "expires_at": "2027-01-01T18:00:00+05:00"
   }
   ```

4. `GET /api/catalog?q=Нан` арқылы партияны табыңыз. Каталог токенсіз ашылады. Жауапта партияның `batch_id` идентификаторы, дүкен, KZT бағалары, қалдық және жарамдылық мерзімі болады.

## Жоба мүмкіндіктері

- Сатып алушы, сатушы және әкімші рөлдері.
- Тіркелу, email мен құпиясөз арқылы кіру және жеке кабинет.
- Өнімдер каталогы, іздеу, сүзгілер және сұрыптау.
- Өнім карточкасында баға, жеңілдік, фото, қолжетімді қалдық және жарамдылық мерзімі.
- Таңдаулылар, себет, ұсыныстарды WSM әдісімен салыстыру және брондау.
- Жеткізу немесе дүкеннен алып кету арқылы тапсырыс беру.
- Сатушы панелі: ұсыныстарды, партияларды, бағаны, қалдықты және тапсырыстарды басқару.
- Әкімші панелі: пайдаланушыларды, сатушыларды, санаттарды және аналитиканы басқару.
- Хабарландырулар, әрекеттер тарихы және деректерді экспорттау.
- Сатып алушыларға нақты әрекеттерге негізделген ұсыныстар; сатушыларға сұраныс пен жеңілдік бағасы бойынша талдау.

## Технологиялық негіз

- **Python** — негізгі тіл.
- **PySide6** — desktop-қосымшаның интерфейсі.
- **PostgreSQL** — жобада қолданылатын жалғыз дерекқор.
- **Backend API** — интерфейс пен бизнес-логиканың байланыс қабаты.
- **AI-модульдер** — нақты тапсырыстар мен әрекеттер жеткілікті болғанда ұсыныстар мен талдау жасауға арналған.

## Даму қағидалары

- SQLite қолданылмайды. Даму және интеграциялық тексерулер PostgreSQL арқылы жүргізіледі.
- Интерфейс дерекқорға тікелей қосылмайды; API, бизнес-логика және деректерге қол жеткізу бөлек модульдерде болады.
- Құпиясөздер қауіпсіз хэшпен сақталады. Құпия кілттер мен `.env` файлдары GitHub-қа жүктелмейді.
- API қателері түсінікті болуы керек және құпия деректерді, SQL мәтінін немесе traceback-ті көрсетпеуі керек.
- Жұмыс істемейтін функция жалған сәтті жауаппен немесе mock-дерекпен алмастырылмайды.
- AI нәтижелері тек нақты дерекке сүйенеді. Дерек жеткіліксіз болса, жүйе оны ашық көрсетеді (`insufficient_data`); ойдан шығарылған дәлдік пен метрикалар жарияланбайды.
- AI/сұраныс болжамын бағалағанда дереккөзді, уақыт бойынша бөлу тәсілін, салыстыру baseline-ын, модель нұсқасын және нақты өлшенген нәтижелер мен шектеулерді тіркеу керек.
- Әр өзгеріс тармақ бойынша әзірленіп, тексерілген diff-пен біріктіріледі. Демоның жұмыс істейтіні нақты сценариймен тексерілгеннен кейін ғана мәлімделеді.

## Жүйе құрылымы

Қосымша модульдік түрде құрылады: PySide6 интерфейсі Backend API арқылы бизнес-логикамен жұмыс істейді, ал деректер PostgreSQL жүйесінде сақталады. Интерфейс дерекқорға тікелей қосылмайды.

## Қазіргі күйі

Тіркелу, жүйеге кіру, дүкен ашу, партия жариялау, каталогтан іздеу, сатып алушының брондауы (`Idempotency-Key` қолдауымен) және сатушының тапсырыстарды қарап, «Растау» арқылы қабылдауы FastAPI API мен PySide6 desktop-қосымшасында қолжетімді. Келесі кезең — сатып алушы тапсырыстарының тізімін және статусын қосу. AI мүмкіндіктері нақты деректер жиналғаннан кейін кезең-кезеңімен қосылады.
