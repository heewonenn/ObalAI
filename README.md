# ObalAi

**Тамақ қалдықтарын азайтуға арналған ақылды платформа**

ObalAi дүкендерге, супермаркеттерге, кафелер мен мейрамханаларға жарамдылық мерзімі жақындаған өнімдер мен дайын тағамдарды жеңілдікпен ұсынуға көмектеседі. Сатып алушылар қолжетімді ұсыныстарды қарап, салыстырып, алдын ала брондап, жеткізуге немесе алып кетуге тапсырыс бере алады.

## Демо

**Жарияланған демо-сайттың сілтемесі әзірге жоқ.** Демо дайын болып жарияланғаннан кейін осы бөлімге нақты сілтеме қосылады.

## Жоба мүмкіндіктері

- Сатып алушы, сатушы және әкімші рөлдері.
- Тіркелу, email мен құпиясөз арқылы кіру және жеке кабинет.
- Өнімдер каталогы, іздеу, сүзгілер және сұрыптау.
- Өнім карточкасында баға, жеңілдік, фото, қолжетімді қалдық және жарамдылық мерзімі.
- Таңдаулылар, себет, ұсыныстарды WSM әдісімен салыстыру және брондау.
- Жеткізу немесе дүкеннен алып кету арқылы тапсырыс беру.
- Сатушы панелі: ұсыныстарды, партияларды, бағаны, қалдықты және тапсырыстарды басқару.
- Әкімші панелі: пайдаланушыларды, сатушыларды, санаттарды және аналитиканы басқару.
- Хабарландырулар, әрекеттер тарихы және деректерді экспорттау.
- Сатып алушыларға нақты әрекеттерге негізделген ұсыныстар; сатушыларға сұраныс пен жеңілдік бағасы бойынша талдау.

## Технологиялық негіз

- **Python** — негізгі тіл.
- **PySide6** — desktop-қосымшаның интерфейсі.
- **PostgreSQL** — жобада қолданылатын жалғыз дерекқор.
- **Backend API** — интерфейс пен бизнес-логиканың байланыс қабаты.
- **AI-модульдер** — нақты тапсырыстар мен әрекеттер жеткілікті болғанда ұсыныстар мен талдау жасауға арналған.

## Даму қағидалары

- SQLite қолданылмайды. Даму және интеграциялық тексерулер PostgreSQL арқылы жүргізіледі.
- Интерфейс дерекқорға тікелей қосылмайды; API, бизнес-логика және деректерге қол жеткізу бөлек модульдерде болады.
- Құпиясөздер қауіпсіз хэшпен сақталады. Құпия кілттер мен `.env` файлдары GitHub-қа жүктелмейді.
- API қателері түсінікті болуы керек және құпия деректерді, SQL мәтінін немесе traceback-ті көрсетпеуі керек.
- Жұмыс істемейтін функция жалған сәтті жауаппен немесе mock-дерекпен алмастырылмайды.
- AI нәтижелері тек нақты дерекке сүйенеді. Дерек жеткіліксіз болса, жүйе оны ашық көрсетеді (`insufficient_data`); ойдан шығарылған дәлдік пен метрикалар жарияланбайды.
- AI/сұраныс болжамын бағалағанда дереккөзді, уақыт бойынша бөлу тәсілін, салыстыру baseline-ын, модель нұсқасын және нақты өлшенген нәтижелер мен шектеулерді тіркеу керек.
- Әр өзгеріс тармақ бойынша әзірленіп, тексерілген diff-пен біріктіріледі. Демоның жұмыс істейтіні нақты сценариймен тексерілгеннен кейін ғана мәлімделеді.

## Жүйе құрылымы

Қосымша модульдік түрде құрылады: PySide6 интерфейсі Backend API арқылы бизнес-логикамен жұмыс істейді, ал деректер PostgreSQL жүйесінде сақталады. Интерфейс дерекқорға тікелей қосылмайды.

## Қазіргі күйі

Жоба бастапқы әзірлеу сатысында. Қазіргі басымдықтар — PostgreSQL деректер моделін бекіту, модульдік құрылымды дайындау және тіркелуден бастап тауарды брондауға дейінгі негізгі сценарийді жасау. AI-мүмкіндіктері нақты деректер пайда болғаннан кейін кезең-кезеңімен қосылады.
